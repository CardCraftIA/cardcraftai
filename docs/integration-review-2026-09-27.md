# CardCraftAI integration review — TEST

## Game

- 120 cards and four languages are implemented. Match decks choose one edition per character; solo and private online share deterministic scoring. No public matchmaking, player moderation, ranking, trading or economy exists.
- Character portraits previously reused the same pose for ten editions. The 108 evolution editions now have individual action poses and expressions, composed with their matching power scene. Art is original to Nacarim.
- The installed GitHub connector can inspect and update repository code. No missing game-specific connector is required for the present turn-based rooms. More concurrent users will require load testing of the Streamlit fragment polling and the match storage/transaction path before a competitive launch.

## Brevo email

The repository has no Brevo SMTP configuration or Brevo API calls. Supabase Auth sends signup confirmation and password reset emails; its hosted SMTP configuration is outside this repository. Do not claim Brevo is connected from the privacy-policy mention. The recommended integration is Brevo SMTP relay configured in the **TEST Supabase Auth custom SMTP settings**, with a verified sender domain and an actual confirmation/reset delivery test. Keep the SMTP password in the Supabase dashboard, not Streamlit secrets or code. Check rate limits and logs for bounced/invalid email. Do not send a second confirmation email from the app: the Auth confirmation token is generated by Supabase.

The TEST project's Edge Function listing contains only `mercadopago-create-preference` and `mercadopago-webhook`; it does not establish SMTP status. The earlier `docs/payment-audit.md` dated September 23 predates those TEST functions and its claim that no endpoint is deployed is stale. Their current source and payment fulfillment were not audited here.

## PayPal subscriptions

`paypal_gateway.py` is a server-only transport for OAuth, subscription creation, provider lookup and webhook signature verification. It is not a checkout. A server-owned subscription order, webhook endpoint, durable idempotent ledger, account/plan/amount/currency reconciliation, cancellation/refund handling, and Sandbox evidence remain absent. `integration_readiness.py` gives a no-secrets status inventory but deliberately cannot enable payments. Leave the PayPal option hidden and do not set `paid_until` from a redirect or AI response. The account and REST app can be configured later without changing this policy.

## Development assistant and other repositories

The public Atlas chatbot answers card questions and must not receive repository credentials. A separate **admin-only** development assistant can inspect explicitly allowlisted repositories through a GitHub App installation token with per-repository access. It may draft integration proposals and tests; writing requires a named target repository and branch, automated checks, and a pull request for human review. No arbitrary repository URL or user-provided token should trigger code execution. The installed GitHub connector already supports the CardCraftAI repository; connect additional repositories by selecting them in the GitHub App installation when requested.

## Release evidence

Offline tests validate modules; they do not prove live Brevo delivery, PayPal settlement or concurrent online match behavior. Production enablement remains gated by those end-to-end tests.
