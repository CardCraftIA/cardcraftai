# Atlas and PayPal integration (TEST)

The CardCraft Shop remains a discovery page with outbound links. Its link cart does not charge customers. CardCraftAI plans and credits are shown on the separate Plans page, where a deterministic payment assistant answers common questions without seeing card data or generating payment instructions.

Atlas now claims one question through `claim_atlas_question()` for every submitted message. The fifth answer includes an upgrade notice; a sixth request is denied. This count is tied to the authenticated Supabase user, not the browser session or chat history. The `atlas_allowances` table has RLS, no client table grants, and an authenticated-only atomic claim function. `paid_until` can only be set by a trusted server process after verified subscription fulfillment. `ATLAS_ALLOWANCE_ENABLED=false` in Streamlit secrets disables the new gate if a rollback is needed. The current staging default is enabled.

**No PayPal charges are enabled yet.** `paypal_gateway.py` prepares OAuth, subscription approval URL creation and webhook signature postback verification. Before showing PayPal checkout, create the PayPal merchant and REST app in Sandbox, define billing product and plan, store credentials only in server secrets, deploy an HTTPS webhook endpoint, verify webhook signatures, fetch and reconcile the subscription/transaction against a server-owned order, and atomically update `paid_until` with idempotency and refund/cancellation handling. Test successful payment, duplicate webhook, cancellation, expiry and refund in Sandbox. Only then enable the UI. Redirects and the chat assistant never grant access.

The existing Mercado Pago one-time credit packages do not extend Atlas chat access. They remain for eligible paid analyses. Subscription checkout is currently disabled, so the five-question gate must stay in TEST until a purchasable Atlas plan is available or the product owner chooses a different continuation policy.
